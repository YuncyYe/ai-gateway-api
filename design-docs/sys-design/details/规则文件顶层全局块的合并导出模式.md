# 规则文件顶层全局块的合并导出模式

> 沉淀来源：`2026-09-30-ai-cache-semantic-cache`（首个落地）与 `2026-10-01-ai-context-compress-control-plane`（第二个落地）。两个模块各自重新推导过同一组决策，本文将其固化为模式，供后续任何"数据面规则文件含顶层全局配置"的模块直接复用。

## 1. 问题场景

BFE 规则类模块的规则文件不只是 `Version + Config[product]` 两段——还有第三类内容：**与具体规则无关的全局调优参数**，且要求随规则文件一起热加载。典型例子：

| 模块 | 规则文件 | 顶层全局块 | 内容 |
|------|----------|-----------|------|
| `mod_ai_cache` | `ai_cache.data` | `Semantic` | 语义检索 topK / 阈值 / 比较方向 |
| `mod_ai_context` | `context_rule.data` | `Defaults` | 触发阈值 / 裁剪长度 / 估算系数 / 改写强度等 8 项 |

控制面必须回答：这些参数存在哪、怎么到 BFE 文件里。

## 2. 模式决策：单例设置表 + 生成器合并

**决策**：全局参数建**单行设置表**（单例资源，GET 读全量 + PUT upsert），由规则文件的 Export Generator 读出并**合并为导出 JSON 的顶层并列键，恒导出**。

**否决的备选——`model/imods` 独立 topic 导出**：

1. BFE 规则加载器只读一个文件（`ai_cache.data` / `context_rule.data`），独立 topic 文件无法被消费；
2. imods 的导出形态是 `Version + Config` 两段，无法表达顶层并列键；
3. imods 适合的是"模块只有全局配置、没有规则集合"的场景（如 `mod_body_process.data`），规则+全局混合的模块不适用。

**两个落地实例对照**（结构完全同构）：

| 维度 | ai-cache | ai-context |
|------|----------|------------|
| 设置表 | `ai_cache_semantic_settings` | `ai_context_settings` |
| 导出顶层键 | `Semantic` | `Defaults` |
| 生成器 | `AICacheRuleGenerator` | `ContextRuleGenerator`（`ConfigTopicProductAIContext = "mod_ai_context"`） |
| Open API | `/ai-cache-semantic-settings` GET/PUT | `/ai-context-settings` GET/PUT |

## 3. 关键语义（每次落地都必须遵守）

1. **空表 = 默认值，不预置默认行**：默认值常量定义在 model 层（如 `DefaultTriggerRatio = 0.7`），注释标注与 BFE `setDefaults` 的**两侧同步义务**；Get 空表返 `(nil, nil)` 由 manager 转默认值对象。避免"库里一行默认值"与常量双真相。
2. **恒导出**：无论规则集合是否为空、设置行是否存在，全局块都出现在导出 JSON 中——生成器无分支，设置与规则生命周期解耦（清空规则不影响全局块）。
3. **设置变更驱动版本流**：全局块进入 MD5 签名内容（`iversion_control.ExportConfig` 标准流程），改设置 → 新签名 → 新版本，conf-agent 正常拉取热加载，零框架改动。
4. **控制面前置校验**：所有数值范围/枚举在 PUT 时 422 拦截（BFE 侧加载失败是最后防线）；`cond` 表达式一律做编译校验（`ConditionExpression`，内部 `condition.Build`，随 go.mod bfe 依赖升级识别新原语——ai-cache / ai-context / traffic-mirror 均如此）。
5. **连接类配置不进导出**：Redis / embedding / 向量库等连接信息放 BFE 静态 `mod_*.conf`，经 conf-agent `CopyFiles` 下发，与规则生命周期无关。
6. **二期字段前向兼容**：控制面新增可选字段（如未来的 `summary`/`override`）时，旧 BFE 对未知字段忽略并计数告警、不拒载——控制面可以先于数据面发版。前提：数据面加载器实现了未知字段容忍（两个模块均已实现并有集成测试覆盖）。

## 4. 何时不适用

- 模块**没有规则集合、只有全局配置**：直接走 imods 独立 topic（`Version + Config` 形态够用）；
- 全局参数**需要按租户/路由差异化**：不能做单例表，应作为规则元素字段（参考 `ai_cache_rules.enable_semantic_cache` 的规则级开关形态）。
