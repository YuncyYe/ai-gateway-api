# 流量镜像规则与导出

## 1. 概述

流量镜像规则（`traffic_mirror_rules`）是 AI 网关流量镜像能力（traffic mirroring / shadow traffic）的控制面配置入口：生产请求正常转发的同时，BFE `mod_traffic_mirror` 模块把请求副本（方法/路径/Header/Body，可按规则改写）异步发往镜像目标集群，响应完整读空后丢弃，结果仅入统计（Prometheus 指标 + 访问日志 `mirror_hit`/`mirror_cluster` 字段）。典型用途：新集群/新模型发布前真实流量验证（双跑）、fallback 集群热备演练。

镜像请求是网关内部 fire-and-forget 子请求：不触发配额扣减、不重复鉴权、不计入客户用量。规则文件由 ai-gateway-api 生成、conf-agent 轮询拉取并触发 BFE 热加载，与既有配置导出链路（`topic + generator + MD5 签名 + config_versions + Inner API 轮询`）完全一致，纯登记式扩展，导出框架零改动。

## 2. 资源模型

### 2.1 集合资源 `traffic_mirror_rules`

- Open API 仅暴露集合级读写：`GET /open-api/v1/traffic-mirror-rules`（全量查询）+ `PUT /open-api/v1/traffic-mirror-rules`（整体替换），照 `ai-cache-rules` / `global-route-rules` 先例；
- **无 `/{id}` 端点**：`id` 为表内自增排序字段，**不暴露到 API**；
- **无 `enabled` 字段**：PUT 提交的列表即生效集合，"禁用一条规则" = 从列表移除；单条临时停用 = `percentage=0`（命中但不采样）；
- **一组有序规则，first-match-wins**：顺序 = PUT 数组顺序 = `id` 升序 = GET 返回顺序 = 导出数组顺序；不设显式 `priority` 字段；
- **`cond` 必填**，全部匹配显式写 `default_t()`（与 `ai_cache_rules` 一致）：空串无法区分"故意全匹配"与"漏传"，而空 cond 静默生效 = 100% 流量镜像 = 双倍推理成本，不接受隐式默认；
- PUT 为单事务整体重建（delete-all + insert-all）：不在提交列表中的规则即删除；`{"rules": []}` 清空全部规则（**镜像总开关 = 清空本集合**）。

### 2.2 与 ai_cache_rules 的关键差异

| 维度 | ai_cache_rules | traffic_mirror_rules |
|------|----------------|----------------------|
| `cond` | 必填 | 必填（一致；全匹配显式 `default_t()`） |
| 引用校验 | 无引用字段 | **`mirror_cluster` 存在性校验**（endpoint 层，422） |
| cond 集合内去重 | 不做（BFE 兜底） | **必须做**（BFE `Check` 拒绝重复 cond） |
| 导出字段 | 最小字段集（5 个，余者 BFE 填默认） | **规则全字段**（7 个，无预留字段） |
| 默认值风险 | 低 | `percentage` 缺省 100 = 全量镜像 = 双倍推理成本，Web 表单引导保守值 |
| 默认黑名单 | 不涉及 | `remove_headers` 缺省由控制面填 `["Authorization","Cookie","X-Api-Key"]` |
| topic | `mod_ai_cache` | `mod_traffic_mirror` |

## 3. 数据模型

### 3.1 表结构

```sql
CREATE TABLE `traffic_mirror_rules` (
  `id` BIGINT AUTO_INCREMENT PRIMARY KEY COMMENT '主键ID（排序/优先级用，不暴露API）',
  `name` VARCHAR(128) NOT NULL COMMENT '规则名称（集合内唯一，可读性/审计用）',
  `cond` TEXT COMMENT 'BFE条件表达式；空串/NULL=全匹配（控制面API要求必填并显式default_t()）',
  `mirror_cluster` VARCHAR(128) NOT NULL COMMENT '镜像目标cluster名（引用cluster表，PUT时校验存在性）',
  `percentage` INT NOT NULL DEFAULT 100 COMMENT '镜像采样百分比（0-100），0=命中但不采样',
  `remove_headers` TEXT COMMENT '镜像副本剔除Header黑名单（JSON数组）；NULL=导出时填默认黑名单',
  `set_headers` TEXT COMMENT '镜像副本注入Header（JSON对象）；NULL=不注入',
  `body_rewrites` TEXT COMMENT 'body字段改写（JSON数组[{"path","value"}]）；一期path仅允许model',
  `path_rewrite` VARCHAR(1024) COMMENT '镜像路径整体替换（query保留）；NULL/空串=不改写',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  UNIQUE KEY `uk_name` (`name`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='流量镜像规则表';
```

要点：

- **无 `enabled` 列**（全量替换模型下冗余，见 §2.1）；
- `uk_name` 唯一键兜底集合内重名（服务端校验先行，DB 为最后防线）；
- **`remove_headers` 列必须保留 NULL 语义**：NULL = 用户未提交（导出时控制面填默认黑名单），`'[]'` = 用户显式清空（导出不剔除）；
- SQLite 版本（`db_ddl_sqlite.sql`）照 `ai_cache_rules` 的 SQLite 惯例改写：类型映射（`BIGINT`→`INTEGER`、`TEXT`/`VARCHAR`→`TEXT`、`DATETIME`→`TEXT`）+ `updated_at` 由触发器维护；新表对存量库为零迁移。

### 3.2 Open API 数据形态

```json
{
  "rules": [
    {
      "name": "mirror-gpt4o-to-shadow-v2",
      "cond": "req_path_prefix_in(\"/v1/chat/completions\", true) && req_body_json_in(\"model\", \"gpt-4o\", false)",
      "mirror_cluster": "cluster_shadow_v2",
      "percentage": 10,
      "set_headers": {"X-Shadow-Env": "pre-release"},
      "body_rewrites": [{"path": "model", "value": "deepseek-v3"}]
    },
    {
      "name": "mirror-all-to-standby",
      "cond": "default_t()",
      "mirror_cluster": "cluster_standby",
      "percentage": 100,
      "path_rewrite": "/v1/internal/chat/completions"
    }
  ]
}
```

| 字段 | 类型 | 说明 | 合法性条件 |
|------|------|------|------------|
| `rules` | array | 规则列表，按数组顺序匹配（first-match-wins），顺序即优先级 | 必填；`null` 按 `[]` 处理（清空全部规则） |
| `rules[].name` | string | 规则名称（可读性/审计用，非寻址键） | 必填；1-128 字符；同一集合内不得重复 |
| `rules[].cond` | string | BFE 条件表达式，命中即启用镜像；全匹配显式 `default_t()` | **必填**；必须能通过 BFE `condition.Build` 编译；同一集合内不得重复 |
| `rules[].mirror_cluster` | string | 镜像目标 cluster 名 | 必填；服务端校验存在性（不存在 → 422） |
| `rules[].percentage` | int | 镜像采样百分比；`0` = 命中但不采样 | 非必填；未传时默认 `100`；∈ [0, 100] |
| `rules[].remove_headers` | []string | 镜像副本剔除的 Header 黑名单；缺省 = 服务端填默认黑名单，显式 `[]` = 不剔除 | 非必填；元素非空 |
| `rules[].set_headers` | object | 镜像副本注入的自定义 Header；`X-Bfe-Mirror` 由 BFE 缺失时兜底注入 `true` | 非必填；key/value 非空 |
| `rules[].body_rewrites` | []object | body 字段改写（新模型双跑验证） | 非必填；元素 `path` 必填且一期仅 `"model"`；`value` 必填非空 |
| `rules[].path_rewrite` | string | 镜像路径整体替换（query 保留） | 非必填；非空时必须以 `/` 开头 |

响应只读字段（仅 GET/PUT 响应携带，提交时忽略）：`rules[].created_at`、`rules[].updated_at`（RFC3339）。规则 `id` 为内部排序字段，不出现在 API 请求与响应中。

## 4. Open API 读写语义

### 4.1 接口

| Method | Path | 权限 | 说明 |
|--------|------|------|------|
| GET | `/open-api/v1/traffic-mirror-rules` | `FeatureTrafficMirror + ActionRead` | 全量查询；空集合返回 `{"rules": []}`；按优先级升序返回（顺序同导出到 BFE 的顺序） |
| PUT | `/open-api/v1/traffic-mirror-rules` | `FeatureTrafficMirror + ActionUpdate` | 全量更新（整体替换）；返回更新后全量集合 |

### 4.2 校验（`lib/validate.TrafficMirrorRules`，任一失败则整个 PUT 422，集合不变）

| 校验项 | 规则 |
|--------|------|
| `rules` | `null` 按 `[]` 处理；单条为 null 拒绝 |
| 每条 `name` | 非空、1-128 字符 |
| 每条 `cond` | 必填 + `ConditionExpression`（内部调 BFE `condition.Build` 编译） |
| 每条 `mirror_cluster` | 非空、1-128 字符（**存在性在 endpoint 层**：`icluster_conf.ClusterManager.FetchClusterList` 按名批量过滤，不存在 → 422） |
| 每条 `percentage` | ∈ [0, 100] |
| 每条 `remove_headers` | 元素非空 |
| 每条 `set_headers` | key/value 非空 |
| 每条 `body_rewrites` | 元素 `path` = `"model"`（一期）；`value` 非空 |
| 每条 `path_rewrite` | 空或 `/` 开头 |
| 集合内 `name` 唯一 | 遍历查重（422，请求集合内部矛盾，不用 409） |
| 集合内 `cond` 唯一 | 遍历查重（如两条均写 `default_t()` → 422） |

控制面校验把错误拦在写入前（fail-fast）；BFE 侧校验（最后防线）：`mirrorCluster` 非空、`percentage ∈ [0,100]`、`cond` 编译通过、`bodyRewrites[].path = "model"`、同一 product 内 `cond` 不可重复（含空 cond）。

### 4.3 事务重建

PUT 的执行语义为**单事务整体重建**：

1. `itxn.TxnStorager.AtomExecute` 开启事务（禁止 ad-hoc 事务）；
2. delete-all：删除 `traffic_mirror_rules` 全表旧数据；
3. insert-all：按提交数组顺序逐条写入；新 `id` 自增序即优先级序，与 GET/导出顺序一致；
4. 事务失败整体回滚，集合保持原状；
5. 事务成功后记录操作日志（`resource_type=traffic_mirror_rule`，`before`/`after` 为整个集合快照）；失败也记录一条失败审计（照 ai_cache 的失败审计先例）。

本接口为整组规则的唯一写入口，配置生效时延 = conf-agent 轮询周期（`ReloadIntervalMs`）+ BFE 热加载时间。

## 5. 导出契约（冻结）

> 本节是控制面/数据面的**接口契约**，已与 BFE `mod_traffic_mirror` 规则加载器（`bfe_modules/mod_traffic_mirror/mirror_rule_load.go` 的 `MirrorRuleConfFile`）逐字段核对冻结。任何一侧改字段必须先改本节并知会另一侧。

### 5.1 文件结构

```json
{
  "Version": "20260925103000",
  "Config": {
    "<product>": [ /* MirrorRuleConfFile 数组，first-match-wins */ ]
  }
}
```

- `Version` / `Config` 首字母大写：conf-agent 提取版本与配置的**硬契约**；
- `<product>` 从运行时配置取：`stateful.DefaultConfig.RunTime.AIRouteInnerProductName`（默认 `AI_product`），**不要硬编码**——与 mod_ai_cache 导出一致；
- `Config` 的 value 为数组；数组顺序 = `id` 升序 = PUT 提交顺序。

### 5.2 字段 tag 全表（`MirrorRuleConfFile`）

| 导出 JSON tag | Go 字段 | 一期是否导出 | BFE 缺省填充（`setDefaults`） | BFE 校验（`Check`） |
|---------------|---------|--------------|------------------------------|---------------------|
| `cond` | `Cond *string` | **是（恒输出非空）** | `nil → ""` | 非空必须 `condition.Build` 编译通过 |
| `mirrorCluster` | `MirrorCluster *string` | **是（必导、显式非空）** | 无默认——**缺失即加载失败**（`CheckNilField`） | 非空 |
| `percentage` | `Percentage *int` | 是 | `nil → 100` | ∈ [0, 100] |
| `removeHeaders` | `RemoveHeaders []string` | 是（**控制面缺省填默认黑名单**；显式 `[]` 导出不剔除） | `nil → []`（**注意：BFE 默认不剔除，默认黑名单是控制面行为**） | - |
| `setHeaders` | `SetHeaders map[string]string` | 是（空输出 `{}`） | `nil → {}` | - |
| `bodyRewrites` | `BodyRewrites []*MirrorBodyRewriteConfFile` | 是（空输出 `[]`） | `nil → []` | 元素 `path` 必须为 `"model"`（一期硬校验）；`path`/`value` 必填指针 |
| `pathRewrite` | `PathRewrite *string` | 是（空输出 `""`） | `nil → ""` | - |

**导出全字段策略**：`mod_traffic_mirror` 规则字段共 7 个且全部是规则语义字段，无 ai_cache 那种"二期预留字段"，一期即全字段恒导出（空值输出零值，不用 `omitempty`，导出物显式可 diff）。

**易错点**：

1. **同 product 内 `cond` 唯一（BFE 对空 cond 重复也拒绝）**：控制面 `cond` 必填后，重复只可能来自两条相同表达式（如都写 `default_t()`），PUT 校验必须拦截（与 ai_cache 的"不去重"决策不同）；
2. **`removeHeaders` 两侧默认值语义不同**：BFE `setDefaults` 默认空列表（不剔除任何头）；默认黑名单 `["Authorization","Cookie","X-Api-Key"]` 是**控制面在导出时**对"用户未提交 `remove_headers`"的填充行为。两侧联调时若以"直接手写 BFE conf"验证默认行为会得出相反结论；
3. **`X-Bfe-Mirror` 由 BFE 缺省注入**（`buildMirrorHeader`：用户未配置时置 `true`），控制面 `setHeaders` 不需要、也不应默认携带；
4. `bodyRewrites` 一期仅 `path="model"`，BFE `Check` 硬校验；控制面 Open API 层同步校验；
5. BFE 对指针字段（`cond`/`mirrorCluster`/`percentage`/`pathRewrite`）做 `CheckNilField`——控制面漏导 `mirrorCluster` 属 P0 级契约事故（导出 struct 中该字段为非指针必填，漏填编译期即报错）。

## 6. 生成器流程

### 6.1 入口

```go
func (m *TrafficMirrorManager) ConfigExport(ctx context.Context, lastVersion string) (*iversion_control.ExportData, error)
```

### 6.2 `TrafficMirrorRuleGenerator` 流程

1. 查全部规则，按 `id` 升序（**无 enabled 过滤**——提交列表即生效集合）；
2. 逐条组装导出结构：`cond`、`mirrorCluster`、`percentage`、`removeHeaders`（**列为 NULL 时填默认黑名单常量** `DefaultSensitiveHeaders = ["Authorization","Cookie","X-Api-Key"]`；显式值原样）、`setHeaders`（NULL → `{}`）、`bodyRewrites`（NULL → `[]`）、`pathRewrite`（NULL → `""`）；
3. 组装 `Config[AIRouteInnerProductName] = 规则数组`（导出专用 struct 与 §5.2 tag 完全一致，定义在 `model/traffic_mirror/` 内）；
4. 空表时导出空数组（product 键仍 present，值为 `[]`）；
5. 套 `iversion_control.ExportConfig(ctx, ConfigTopicProductTrafficMirror, generator)` 标准流程：生成数据 → MD5 签名 → 比对 `config_versions`（`name="mod_traffic_mirror"`）→ 签名相同返回旧版本（增量，HTTP Data 为 null）→ 不同则插新版本（版本号 = 时间戳 `20060102150405`，同 Topic 严格单调递增，机制见《InnerAPI配置导出与版本控制.md》）。

topic 常量 `ConfigTopicProductTrafficMirror = "mod_traffic_mirror"` 定义在 `model/traffic_mirror/traffic_mirror_manager.go` 内（与 ai_cache 的 topic 定义在自身包内一致）。

### 6.3 Inner API 端点

```go
// endpoints/innerapi_v1/traffic_mirror/export.go
var ExportRoute = &xreq.Endpoint{
    Path:       "/configs/traffic-mirror-rule",
    Method:     http.MethodGet,
    Handler:    xreq.Convert(ExportAction),
    Authorizer: iauth.FA(iauth.FeatureTrafficMirror, iauth.ActionExport),
}

func ExportAction(req *http.Request) (interface{}, error) {
    param, err := export_util.NewExportFromReq(req) // 解析 version
    if err != nil {
        return nil, err
    }

}
```

conf-agent 侧登记（`conf-agent.toml`，非本仓库代码改动）：`[Reloaders.mod_traffic_mirror]`：`ConfAPI=/inner-api/v1/configs/traffic-mirror-rule`、`ReloadFile=mirror_rule.data`、`BFEReloadAPI=/reload/mod_traffic_mirror`、`CopyFiles=["mirror_rule.data","mod_traffic_mirror.conf"]`。

## 7. 模块基础配置不下发

`mod_traffic_mirror.conf`（分层超时 `ConnectTimeoutMs`/`TTFBTimeoutMs`/`TotalTimeoutMs`、`MaxMirrorBodyBytes`、`MaxResponseBodyBytes`、`MaxConcurrent`、`QueueCapacity`、`CircuitBreakerFailThreshold`、`CircuitBreakerCooldownSec`）**不进导出链路**，放 BFE 静态 conf 文件，由 conf-agent `CopyFiles` 随规则文件一起落盘。理由：

- 调参项与规则生命周期不同（近乎不变）；
- 与 `mod_ai_cache.conf`（Redis 连接）同款决策，减少导出链路复杂度与敏感面。

## 8. 与 ai_cache_rules 导出的差异

| 维度 | ai_cache_rules 导出 | traffic_mirror_rules 导出 |
|------|---------------------|---------------------------|
| 导出字段 | 最小字段集（5 个），余者 BFE 填默认 | **规则全字段**（7 个恒输出，无预留字段） |
| cond 缺省 | 不允许（必填） | 同样必填（全匹配显式 `default_t()`，本接口不生成空 cond） |
| 默认值责任 | BFE 分担较多 | 控制面分担较多（默认黑名单、percentage 显式导出） |
| 引用完整性 | 无引用字段 | `mirror_cluster` 控制面存在性校验 |
| 数据面失败兜底 | BFE 加载报错 | BFE 加载报错 + 运行时 `fail_total{reason="resolve"}`（控制面校验兜住后者） |
| 产物文件 | `ai_cache.data` | `mirror_rule.data` |
| 版本控制 | `mod_ai_cache` topic | `mod_traffic_mirror` topic（独立版本线） |

## 9. BFE 侧预期行为

BFE `mod_traffic_mirror` 收到 `mirror_rule.data` 并热加载后：

1. `HandleForward` 回调（clusterInvoke 选中后端后）按数组顺序逐条匹配规则（first-match-wins）；
2. 命中后：`CtxMirrored` once 标记去重（AI fallback 重试不重复镜像）→ 百分比采样 → body 拷贝（超限跳过并计数）→ Header 黑名单剔除 + `X-Bfe-Mirror`/`X-Bfe-Logid` 注入 + body `model` 改写 → 快照提交异步任务，**主链路零等待**；
3. 异步 goroutine：熔断检查 → 经全局 BalTable 解析 `mirrorCluster` 后端（`PickBackend`）→ 分层超时发送 → **SSE 响应完整读空至 `[DONE]`**（客户端断连不取消镜像连接，总时长兜底）→ 轻量解析 `usage`/`error`/`finish_reason` → 计 Prometheus 指标；
4. 无规则命中：天然放行，零镜像流量；
5. 镜像请求不经过 token auth / rate limit / 配额扣减（模块内独立 `http.Client` 直发镜像后端）；访问日志记录 `mirror_hit`（842）/`mirror_cluster`（843），异步结果不回写（844-850 一期保留为空）。

> BFE 具体镜像实现（异步发送器、SSE 读空、熔断器、Prometheus 指标）不在本文档范围；模块调参以静态 `mod_traffic_mirror.conf` 为准（§7）。

## 10. 边界情况

| 场景 | 行为 |
|------|------|
| PUT `{"rules": []}` | 清空全部规则；导出空数组（product 键仍 present），BFE 侧零镜像流量（镜像总开关关闭） |
| PUT 部分规则校验失败 | 整个 PUT 422，单事务回滚，GET 集合不变 |
| 集合内 `name` 重名 | 422（请求集合内部矛盾，不用 409）；`uk_name` 为 DB 最后防线 |
| 集合内 `cond` 重复（如两条 `default_t()`） | 422（控制面 fail-fast）；BFE `Check` 继续兜底 |
| `cond` 编译失败 | 422（Open API 层 `ConditionExpression` 校验） |
| `mirror_cluster` 不存在 | 422（endpoint 层存在性校验）；若绕过控制面直接写 BFE conf，BFE 运行时仅计 `fail_total{reason="resolve"}` |
| 漏导 `mirrorCluster` | BFE `CheckNilField` 加载失败（P0 级契约事故）；单测对 marshal 结果做 JSON key 精确断言防回归 |
| `remove_headers` 缺省 vs 显式 `[]` | 缺省 → 导出默认黑名单（剔鉴权/会话头）；显式 `[]` → 导出不剔除（合规自负） |
| 导出后规则又变更 | 下次轮询时 MD5 签名变化 → 新版本号 → conf-agent 拉取并热加载；生效时延 = 轮询周期 + 热加载时间 |
