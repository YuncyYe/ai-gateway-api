# 管理面访问控制（IP 白名单）

> 本文沉淀管理面 IP 白名单机制的落地实现，基于实际代码而非设计草案。
> 变更说明见 `design-docs/modifications/2026-10-04-mgmt-ip-whitelist/`；
> 需求与实现方案见 `document-ai-gateway/迭代系统设计/v0.8/管理面IP白名单/`。

---

## 1. 机制定位

管理面（Dashboard 静态资源 + `/open-api/v1` + `/inner-api/v1`，单端口默认 8183）在鉴权之前的网络层访问控制。与数据面白名单（`api_keys.subnet`，BFE `mod_ai_token_auth`）互补：数据面按"每个虚拟密钥"配置，管理面按"路径前缀分组"全局配置。

三个刻意的设计选择：

1. **配置在服务端 toml（`[AccessControl]` 段），不在 DB、不经 OpenAPI**——白名单保护的是控制面 API 自身，若经 API 管理则"错误配置锁死"后无法自救（鸡生蛋）。配置随部署物分发（裸机文件 / K8s ConfigMap）。
2. **默认关闭**（`Enable=false` 完全旁路），存量配置文件零改动升级。
3. **网络层先于鉴权**：未过白名单的请求不进入 Session/Token 校验，直接 403（`xerror` 新增 `Access.Forbidden` → `Resolve()` 映射 HTTP 403，经 `xreq.Result` 渲染，与 401/402 同族）。

## 2. 代码结构（实际实现）

| 文件 | 内容 |
|------|------|
| `stateful/access_control.go` | `AccessControlConf`/`AccessRuleConf` 配置结构；`CompiledAccessControl` 编译产物；`CompileAccessControl()`（启动与热加载共用）；`ReloadAccessControl()`；`LoadCompiledAccessControl()`/`StoreCompiledAccessControl()`（`atomic.Value` 载体） |
| `stateful/config.go` | `Config.AccessControl` 字段；`LoadConfig` 内：留存 `confFilePath` → 校验（含自定义 `cidr` tag）→ 编译 → 原子写入 |
| `stateful/metrics.go` | `MetricMgmtAccessReject`（`mgmt_access_reject_total{rule}`）；`NewMonitorServerWithRun` 注册 `/reload/access_control` |
| `endpoints/middleware/ip_probe.go` | `IPProbeAction`（中间件主体）、`resolveClientIP`（可信代理 XFF 解析）、`matchRule`（最长前缀）、`prefixContains` |
| `endpoints/middleware/convert.go` | `McIPProbe = convert(IPProbeAction)` |
| `endpoints/router.go` | 全局链插入 `router.Use(middleware.McIPProbe)` |
| `lib/xerror/wrap.go` / `resolve.go` | `etAccessForbidden = "Access.Forbidden"`、`WrapAccessForbiddenErrorWithMsg`、403 映射 |

中间件位置约束（`router.go` 顺序注释中明示，勿移）：**MCLogger 之后**（拒绝事件进访问日志）、**MCCors 之前**（403 对跨域预检同样生效）。Dashboard 静态分支走 `NotFoundHandler`，而 mux v1.8 的 ServeHTTP 不对 NotFoundHandler 应用 `Use` 中间件（集成测试 MAC-1-003 实证：白名单曾整体绕过静态路径），故 `router.go` 对该分支手动包裹同一链条（Recovery→Logger→IPProbe→Cors）。

## 3. 规则模型与匹配

- 规则 = `{Name, PathPrefix, Subnets, Audit}`；编译期按 **PathPrefix 长度降序**预排序，请求取第一条前缀命中（最长前缀优先）。
- 未命中任何规则 → **放行**（默认兼容）；这是与"默认拒绝"相反的显式选择，避免存量路径被意外封锁。
- `Subnets` 支持 IPv4/IPv6 CIDR 与 `/32`、`/128` 单主机；解析用 `net/netip`，IPv4-mapped IPv6（`::ffff:x.x.x.x/n`）归一为纯 IPv4 前缀，保证双栈判定一致。
- `Audit=true` 观察模式：命中拒绝条件只记日志（`audit=true` 标识）与计数，不拒绝——上线前灰度核对"本应拒绝清单"的手段。

## 4. 客户端 IP 判定（可信代理 + XFF）

```
RemoteAddr 不在 TrustedProxies → 直接采用，XFF 完全忽略（伪造头无效）
RemoteAddr 在 TrustedProxies   → XFF 右起向左，跳过可信代理，取首个非可信 IP；
                                 全链皆可信则退回 RemoteAddr
```

- 与 BFE `mod_trust_clientip` 同源算法，支持多级反代（LB → BFE → API）。
- 客户端 IP 与解析出的各跳 IP 一律先 `Addr.Unmap()` 再比较。
- `X-Real-IP` 不采用（无链式语义、易伪造）。
- **fail-open**：`RemoteAddr` 无法解析时放行，但计数 `mgmt_access_reject_total{rule="unresolvable"}` 并写日志——白名单自身缺陷不得拖垮管理面。

## 5. 热加载

- 端点：monitor 端口（8284）`/reload/access_control`，handler 签名 `func(url.Values) (string, error)`；框架自带 `isValidForReload` 源地址校验。
- 流程：重读 toml **仅解码 `[AccessControl]` 段**（临时结构，`lib.LoadConfAuto`）→ 与启动期相同的 validator + `CompileAccessControl` → `atomic.Value` 原子替换 → 审计日志（旧规则数 → 新规则数）。任一步失败返回错误，**旧配置保持生效**。
- 校验/编译只有一份代码（`CompileAccessControl` 共用），杜绝"启动拒绝的配置热加载放行"的路径漂移。
- K8s 闭环：ConfigMap 更新 → 卷同步 → 逐 Pod `curl -X POST :8284/reload/access_control`；优雅重启兜底。

## 6. 启动校验（fail-fast）

- `Enable=true` 且任一规则 `Subnets` 为空 → `LoadConfig` 拒绝启动（编译期检查，信息含规则名）。
- 非法 CIDR → validator `cidr` 自定义 tag（`netip.ParsePrefix`）拒绝。
- `0.0.0.0/0` / `::/0` → 编译期告警日志（语义等于未收敛，放行但提示）。

## 7. 实现踩坑记录（复用价值）

1. **validator 对"无 tag 的 struct 切片"不下钻**：`Rules []AccessRuleConf` 最初未加 tag，内层 `Subnets` 的 `dive,cidr` 完全没执行（校验静默通过）。修复：`Rules` 显式标注 `` `validate:"dive"` ``。**教训：嵌套 struct 切片必须显式 `dive`，否则校验形同虚设。**
2. **`LoadConfig` 校验的是整个 `Config`**：单测中只写 `[AccessControl]` 段会因 `[Server]`/`[RunTime]`/`[Databases.bfe_db]` 的 `required` 字段缺失而失败——测试夹带需补全最小合法配置，也反向说明该路径不适合做"单段快速试验"。
3. **`atomic.Value` 作为运行时唯一事实源**：中间件不读 `DefaultConfig.AccessControl`（那是启动快照），每请求 `Load()` 一次，热加载切换无锁无中间态；`StoreCompiledAccessControl` 仅 `LoadConfig` 与 `ReloadAccessControl` 两处调用。
4. **全局 `log.Logger` 在测试中为 nil**：`config_logger.go` 在生产启动时把 `log.Logger` 指向 AccessLogger；中间件单测需先设置（`endpoints/middleware/common_test.go` 的 `setupTestLoggers` 已补 `log.Logger` 设置与还原）。
5. **mux v1.8 对 NotFoundHandler 不应用 `Use` 中间件**（集成测试 MAC-1-003 实证的最严重一条）：设计时依据"全局中间件对静态分支同样生效"的推断写成"零改动覆盖"，实际 gorilla/mux v1.8.0 的 `ServeHTTP` 只对匹配路由套用 `Use` 链，`NotFoundHandler` 裸奔——白名单整体绕过 Dashboard 静态路径（非白名单来源 `GET /` 拿到 200 目录列表）。**单测结构性够不着**（`IPProbeAction` 孤立测试不经过路由分发），由集成测试拦截；修复为 `router.go` 对 NotFoundHandler 手动包裹同一链条。**教训：涉及"框架对边角路径的中间件语义"的推断必须用真实进程集成测试验证，不能凭框架印象写设计。**

## 8. 监控与留痕

- `mgmt_access_reject_total{rule}`（8284 `/monitor/metrics`）；`rule="unresolvable"` 表示 IP 解析失败（fail-open 可见性）。
- 拒绝请求：访问日志（MCLogger 在 McIPProbe 之前，天然落 method/path/RemoteAddr/403）+ 业务日志（规则名、解析 IP、RemoteAddr、XFF、UA、audit 标识）。
- 热加载成功/失败均写审计日志。

## 9. 集成测试

模块 `test/integration/tests/mgmt_access_control/`（design.md + 用例，编号 MAC-x-xxx，共 9 例 10 用例函数）：默认关闭基线、启用放行/三入口拒绝（OpenAPI/Dashboard 静态/InnerAPI）、可信代理 XFF 三态、伪造 XFF 无效、Audit 放行、热加载生效/失败保留旧配置/切换 Audit、启动 fail-fast。测试经 `testutil.StartServerWithExtraConfig`/`StartServerWithMonitor` 注入 `[AccessControl]` 段启动独立真实进程实例；监控端口由 testutil 绑定 127.0.0.1（避免 Windows 防火墙弹窗）。

**该模块的 MAC-1-003 曾实证并拦截第 7 节踩坑 #5 的真实缺陷**（白名单绕过 Dashboard 静态路径），是"集成测试验证框架边角语义"的典型案例。

## 10. 边界与已知限制

- 不做 `X-Real-IP`、不做 fail-close（可用性优先）、不做管理端口拆分（单端口按路径分组是刻意的低成本选择）。
- 监控端口（8284）自身无应用层白名单，靠部署层 NetworkPolicy/安全组收敛（模板见部署样例）。
- 编辑 `ai_gateway_api.toml` 中 `[AccessControl]` 外的其他段后热加载不会生效（reload 只解码单段，刻意为之）。
