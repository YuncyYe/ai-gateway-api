# 下发配置加密（导出口字段级加密）

> 2026-10-05 落地。变更说明（背景/决策/WBS）见
> `design-docs/modifications/2026-10-05-export-config-field-encryption/`，
> API 契约见其中 `api-changes.md`；数据面（BFE 加载点解密）已先行落地
> （`bfe/docs/zh_cn/modifications/2026-10-05-export-config-field-encryption/`）。
> 本文沉淀长期设计事实与实现校准记录。

## 1. 机制概述

控制面导出的两个密钥类 topic 在**导出生成点**做字段级加密，conf-agent 字节透传
零改动，BFE 加载点解密进内存：

| topic | InnerAPI | 加密字段 |
|-------|----------|----------|
| `mod_api_key_rule` | `/configs/mod-api-key` | `tokens.<product>` 的**外层键**（api-key 值本身）；内层 `key` 置空 |
| server_data_conf（`route_rule` topic 的 ClusterConf 段） | `/configs/tls_conf/server_data_conf` | `AIConf.Keys[].Key` |

- 文件保持合法 JSON，非敏感字段（`key_id`/配额/`Name`/`Weight`/`KeyPolicy`/模型映射）
  原样可读（`cat` 排障能力保留）。
- marker 直通：无 `enc$v1$` 前缀按明文处理——灰度、回滚、新旧并存的基本语义。
- 门控：`[Security].EncryptExports`（默认 false）；开关关闭时导出与历史版本字节级一致。

## 2. 信封与密钥（跨仓契约，实现校准记录）

```
enc$v1$<base64( keyID(1B) | nonce(12B) | AES-256-GCM(plaintext)+tag(16B) )>
```

| 项 | 控制面（本仓） | 数据面（BFE，已落地） | 校准说明 |
|----|--------------|----------------------|----------|
| 加密钥 | **keyring 原始 32B 密钥**（`Keyring.EncryptWithRawKey` 绕过 `encKeys` 派生层） | 原始 32B 密钥直接解密 | **实现校准**：取代方案文本的 `HKDF(conf-file-key, "file-enc-key")` 派生设想——BFE 无派生，派生会造成跨仓解不开；导出钥本就单用途，派生无收益 |
| nonce | **确定性**：`HMAC-SHA256(key, plaintext)[0:12]` | 解密侧不感知 | **实现校准（关键结构性约束）**：`data_sign` 为导出内容 MD5，随机 nonce 会使每次导出签名都变、conf-agent 把等价配置当新版本反复推送。代价是相等性泄露（高熵密钥可接受，低熵字段引入时需重评估） |
| keyring 文件 | `xcrypto.LoadKeyringFile` 解析（TOML：`ActiveKeyID` + `[Keys]`） | `bfe_util/crypto.LoadKeyringFile` 同款格式 | 两仓共用同一份文件（`ExportKeyFile` == BFE `[Security].KeyFile），分发到全部 BFE 实例 |
| keyID 选钥 | 加密用 `ActiveExportKeyID`（默认取文件 `ActiveKeyID`） | 按密文首字节 keyID 查 `[Keys]` | 轮换并存期多 keyID 密文共存，无需字段级映射 |

防回归锁：`lib/xcrypto` 单测 `TestEncryptWithRawKeyNotDerived` 断言导出密文**不能被**
HKDF 派生钥解开（GCM 认证失败）、能被原始钥解开——防未来误改派生层。

## 3. 配置与运行时（stateful）

```toml
[Security]
# EncryptExports = false                     # 总开关（默认关）
# ExportKeyFile = "/etc/ai-gateway/keys/export.keys"  # 文件钥 keyring（0600）
# ActiveExportKeyID = 1                      # 新密文 keyID；默认取文件 ActiveKeyID
```

- `exportCrypto{kr, activeID, enabled}` 由 atomic.Value 承载；`enabled = 开关 && keyring
  有效` 在**加载时固化**（避免"开关关但 keyring 有效"误加密）。
- 启动 fail-fast：开关开而文件未配置/损坏/`ActiveExportKeyID` 不在 `[Keys]` → 拒启动；
  开关关而文件损坏 → 仅告警（渐进启用：先配钥、后开开关）。
- `/reload/security` 一并重读 MasterKeyFile 与 ExportKeyFile：各自校验、各自原子替换，
  部分失败保留旧值并返回错误。

## 4. 轮换 runbook（免重启）

1. 生成新钥，`ExportKeyFile` 追加 `[Keys]` 条目并改 `ActiveKeyID = n+1`（旧钥保留）；
2. **BFE 侧先行**：全量实例 keyring 更新（热加载或滚动重启，K8s `subPath` 例外）；
3. 控制面 `POST /reload/security`（热加载生效，免重启）；
4. 触发一次配置变更推进导出版本（**确定性密文下单纯换钥不产生新 `data_sign`**，
   必须有一次内容变更；导出每次全量重新组装，下一导出周期全部密文收敛到新 keyID，
   无 sweep）；
5. 统计观测确认旧 keyID 密文消失后，BFE keyring 摘旧钥、旧钥销毁。

回滚：关 `EncryptExports` → 下一导出周期回到明文 → 任意版本 BFE 可加载（双向安全）。
上线顺序硬约束：**先全量升级 BFE（支持解密），再开开关**；反向错配导致 BFE reload
失败、旧配置滞留。
